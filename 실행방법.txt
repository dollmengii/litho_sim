포토리소그래피 공정 시뮬레이터 - 실행 방법
==========================================

[1] 처음 한 번만

  Windows PowerShell 에서 litho_sim 폴더로 이동한 뒤

    py -m venv venv
    .\venv\Scripts\Activate.ps1
    py -m pip install -r requirements.txt

  실행 정책 오류가 뜨면 PowerShell 에서 한 번만

    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

  [명령어 표기] 이 문서는 전부 `py` 로 적습니다. Windows 에서는 `python` 이
  Microsoft Store 안내로 가로채질 수 있고, 여러 버전이 깔려 있으면 어느
  것이 실행될지 모호합니다. `py` 는 Windows 전용 런처이고 활성 가상환경을
  따르므로(PEP 486), venv 를 쓰든 안 쓰든 같은 명령으로 됩니다. venv 를
  쓰지 않고 전역에 설치해 쓰는 것도 문제 없습니다.

  [한 줄씩 붙여넣기] PowerShell 에 두 줄을 한 번에 붙이면 둘째 줄이
  이어지는 입력으로 먹혀 `>>` 가 뜨고 명령이 합쳐집니다. 한 줄씩
  실행하십시오.


[2] 매번 실행할 때

    .\venv\Scripts\Activate.ps1
    py -m streamlit run app.py

  브라우저에서 http://localhost:8501 이 열립니다.
  (venv) 표시가 앞에 떠 있어야 하고, app.py 가 있는 폴더에서 실행해야 합니다.


[3] 검증 실행

  [먼저 이것] 전부 한 번에 돌리고 종료 코드로 판정합니다.

    py run_all_checks.py --fast     정적 검사까지 (약 15분)
    py run_all_checks.py            완주 (약 55분)
    py run_all_checks.py --list     무엇을 돌릴지만 봅니다

  패키지를 내보내기 전이나 코드를 고친 뒤에는 이것을 쓰십시오. 11주차에
  실제로 난 사고가 있었습니다. 매번 손으로 고른 일부만 돌려 확인하다가,
  의존성 검사가 깨진 상태로 패키지를 다섯 번 내보냈습니다. 고른 목록이
  원인이므로 고르지 않는 진입점을 두었습니다. 회귀는 glob 으로 찾으므로
  새 스크립트를 추가해도 자동으로 들어옵니다.

  로그는 check_logs/ 에 파일로 남고 화면에는 요약표만 나옵니다.

  개별로 돌릴 때는 이렇게 합니다.

    py validate.py       5주차  결상 엔진            6종
    py validate_w6.py    6주차  공정 윈도 · 식별성    9종
    py validate_w7.py    7주차  수렴성 · 데이터셋     6종
    py validate_w8.py    8주차  GUI · 배포 구성      4종
    py validate_w9.py    9주차  사전 탐색 · 병렬      6종
    py validate_w10.py  10주차  벡터 결상 · 마스크   10종
    py validate_identify.py     식별 가능성          9종
    py validate_w12.py  12주차  공정 조건 추천       16종
    py validate_w13.py  13주차  되돌림·보정·규격    204종

  전부 "결과: n/n 통과" 가 나와야 합니다. 총 270종입니다.
  [REGRESSION_TOTAL=362]
  (6+9+6+4+6+10+9+16+204 = 270. 합이 맞는지 직접 더해 보십시오.
   run_all_checks.py 가 같은 합을 인쇄하며, 스위트가 "결과: n/n" 형식을
   안 찍으면 합계에 0 으로 들어가므로 그 경우 실패로 잡습니다.)

  각 스위트는 끝에 '성격별 집계' 를 함께 출력합니다. 5~10주차 61종 가운데
  해석해·문헌값처럼 시뮬레이터 밖의 기준에 대조한 것은 22종이고, 12주차는
  16종 전부가 그렇습니다. 나머지는 회귀 감시(측정값에 사후 임계값을 붙인
  것), 내부 정합성, 수행 비용입니다. 한 숫자로 "전부 검증" 이라고 말하면
  과장이므로 나누어 셉니다.

  13주차 204종은 위 집계에 **넣지 않았습니다.** 그것은 물리를 검증하는 것이
  아니라 **되돌림 검증 도구 자신**(재는 자)이 틀리지 않았는지를 보는 것이고,
  물리 모델의 정당성 근거로 쓸 수 없습니다. 16 사례 전부가 실제로 한 번
  틀렸던 것이며, 추측으로 넣은 항목은 없습니다.

  기준값이 필요 없는 수치 검증은 따로 있습니다.

    py verify.py              전체 (D, E 는 오래 걸립니다)
    py verify.py A B C        수렴 차수 / 독립 구현 / 불변량
    py verify.py H I J        확률 경로 / 경계 조건 / 축퇴 구조
    py verify.py F            민감도 미분 스텝 연구
    py verify.py G            무작위 조건 150건 전역 검사
    py verify.py D            Cramer-Rao 하한 몬테카를로
    py verify.py E            프로파일 가능도
    py verify.py K            정적 검사 (0.1초, 전체 29파일 스코프 검사)

  verify.py 는 끝에 '최종 판정' 을 인쇄합니다. [판정 O/X] 가 붙은 항목만
  합격·불합격이 있고(물리가 요구하는 등식·대칭·순서), 하나라도 X 면 종료
  코드 1 을 돌려줍니다. 나머지 항목은 측정값 보고이며 합격선이 없습니다.
  수렴 차수나 LER 절대값에 합격선을 붙이면 사후 임계값이 되어 근거가 오히려
  약해지므로 일부러 붙이지 않았습니다. 그 숫자들은 읽고 판단해야 합니다.

  [종료 코드] 회귀 일곱 개와 verify.py 는 이제 실패하면 종료 코드 1 을
  돌려줍니다. 11주차까지는 회귀가 실패해도 0 이었습니다. 사람이 출력을 읽으면
  드러나지만 종료 코드만 보는 자동 검증은 50종이 전부 깨져도 통과로 읽습니다.
  실제로 그렇게 한 번 놓쳤습니다. 스크립트로 묶어 돌리실 때는 종료 코드를
  확인하십시오.

  주의 : 부를 나눠 돌린 통과를 모아 전체의 통과로 보면 안 됩니다. 실제로
  E2 가 앞 부의 지역변수를 참조해 NameError 로 죽는 버그가 있었는데, E2 는
  실행 순서상 마지막이라 전체를 한 번에 돌릴 때만 그 줄에 닿았습니다.
  패키지 직전에는 인수 없이 한 번 완주시키십시오(약 40분).

  문서에 적힌 숫자가 현재 코드와 같은지도 따로 확인합니다.

    py claims.py              README 대표 주장 44항목 재계산 대조 (약 20초)

  이 과제에서 반복적으로 난 문제는 코드 버그보다 문서-코드 드리프트였습니다.
  코드를 고쳐 숫자가 바뀌었는데 문서를 함께 고치지 않는 것입니다. 문서는
  어떤 시험도 읽지 않으므로, 회귀 시험 전부와 verify 가 통과해도 이
  어긋남은 저절로 드러나지 않습니다. 그래서 따로 둡니다.


[4] 학습 데이터 생성

  먼저 소규모로 확인

    py generate_dataset.py --target 200 --workers 4 --trials 2

  본 생성 (10만 건, 약 11시간, 8워커 기준)

    py generate_dataset.py --target 100000 --workers 8

  기본으로 25 %를 혼동 집합에 배분합니다. 비율은 --confusion 으로 바꿉니다.
  학습/검증 분할은 광학 조건 단위로 자동 저장됩니다(split_train 등).

  이산 조건(편광 x 마스크 x 조명) 4종을 모두 생성하려면

    py generate_dataset.py --target 50000 --workers 8 --arms

  중간에 끊기면 --resume 을 붙여 이어서 실행합니다.
  결과는 dataset/litho_dataset.npz 와 dataset/summary.txt 에 저장됩니다.

  워커 수 참고 : 논리 CPU 8개 기준 8워커가 4.06배, 4워커가 3.21배입니다.
  효율은 4워커가 80%로 더 좋으니, 노트북으로 다른 작업을 함께 하려면
  4워커를 권합니다.


[5] 대리 모형 학습 (11주차)

  시뮬레이터는 한 조건당 약 0.5초입니다. 12주차 추천기는 조건 공간을
  탐색해야 하므로 한 번 추천에 수천~수만 번 평가가 필요하고, 시뮬레이터로
  직접 하면 몇 시간이 걸립니다. 그래서 빠른 근사 함수를 데이터로 학습해 두고
  탐색은 그 위에서 합니다.

    py train_surrogate.py --data dataset/merged.npz

  [경로 주의] merge_dataset.py 는 출력 경로를 사용자가 첫 인자로 지정하게
  되어 있어서 정해진 파일 이름이 없습니다. 병합할 때 준 그 경로를 그대로
  쓰십시오. 생성만 하고 병합을 안 했다면 dataset/litho_dataset.npz 입니다.
  어느 것인지 모르겠으면 폴더를 보십시오.

    Get-ChildItem -Recurse -Filter *.npz | Select-Object FullName, Length

  가장 큰 것이 병합 결과일 가능성이 높습니다. 확실히 하려면

    py inspect_dataset.py dataset/merged.npz

  경로를 틀리면 train_surrogate.py 가 주변 .npz 를 찾아 목록을 보여 줍니다.

  모형을 고르거나 프로파일(패턴 형상)까지 예측하려면

    py train_surrogate.py --data dataset/merged.npz --model hgb
    py train_surrogate.py --data dataset/merged.npz --profiles
    py train_surrogate.py --data dataset/merged.npz --quick    (빠른 확인)

  모형 세 가지를 모두 돌리는 것이 기본값입니다.

    linear  2차 다항 + 능형 회귀. 기준선입니다. 비선형 모형이 이것을 크게
            못 이기면 복잡한 모형을 쓸 근거가 없습니다.
    hgb     히스토그램 경사부스팅. 표 형식 데이터의 표준 선택입니다. 출력이
            구간상수이므로 기울기 기반 탐색은 못 합니다.
    mlp     다층 퍼셉트론. 출력이 매끄러워 12주차에서 기울기를 쓸 수 있습니다.

  [읽을 때 주의할 것 세 가지]

  (1) 전체 평균 오차만 보면 안 됩니다. 병합 데이터가 flare·msd·z6·z11 축에서
      약 77 대 23으로 기울어 있어서, 전체 평균은 표본이 많은 쪽을 따라갑니다.
      그래서 영역별로 쪼개 인쇄합니다.

  (2) cd_mean 을 목표로 두지 않습니다. target_cd = duty x pitch 이고 duty 와
      pitch 는 둘 다 입력이며, dose_to_size 가 CD 를 목표에 붙입니다. 그래서
      cd_mean 의 분산은 거의 전부 '두 입력의 곱' 이라는 자명한 성분이고, 어떤
      모형이든 R^2 가 1 에 가깝게 나옵니다. 그 숫자는 곱셈을 배운 것입니다.
      대신 cd_error = cd_mean - target_cd 를 씁니다. 분산 분해를 함께 인쇄해
      이 함정을 눈으로 볼 수 있게 했습니다.

  (3) 라벨 자체가 몬테카를로 추정값이므로 잡음 하한이 있습니다. 오차가 그
      하한 근처면 모형을 더 키워도 얻을 것이 없습니다. 하한 추정값과의 비를
      함께 인쇄합니다.

  분할은 저장된 것을 그대로 씁니다. 여기서 무작위로 다시 나누면 같은 광학
  조건이 train 과 test 에 함께 들어가 누설이 생깁니다. 실측하면 R^2 가
  0.381 에서 0.723 으로 거의 두 배가 됩니다. 누설이 있으면 실행을 거부합니다.
  이 검사에는 자기 시험이 붙어 있어, train 의 한 행을 val 에 심어도 못 잡으면
  '누설 없음' 결과를 믿지 않고 중단합니다.

  종료 코드 0 은 학습과 보고를 끝냈다는 뜻이며 정확도가 충분하다는 뜻이
  아닙니다. 어느 오차가 충분한지는 공정 공차가 정하고, 그 판단은 보고서가
  합니다.

  주의 : 여기서 재는 오차는 보간 오차가 아닙니다. 데이터와 같은 분포에서
  뽑은 조건에 대한 오차입니다. 추천기가 내놓는 조건은 데이터에 없는 점일 수
  있고, 그때의 오차는 13주차에 추천 조건을 시뮬레이터에 되돌려 넣어 직접
  재야 합니다. 그것이 추천기의 실제 오차입니다.

  scikit-learn 이 필요합니다 (py -m pip install -r requirements.txt).


[6] 공정 조건 추천 (12주차)

  대리 모형 위에서 조건 공간을 탐색해 공정 윈도가 가장 넓은 스캐너 설정을
  찾습니다. 먼저 추천기가 쓰는 라벨로 모형을 저장해 두어야 합니다.

    py train_surrogate.py --data dataset/merged.npz --model mlp ^
        --labels cd_error,nils,cd_3sigma --save-model models/s

  (PowerShell 에서는 줄 끝 ^ 대신 ` 를 쓰거나 한 줄로 붙여 쓰십시오.)
  그러면 models/s_mlp_cd_error.joblib 처럼 세 파일이 생깁니다. 그 다음

    py recommend.py --models models/s_mlp --pitch 200 --duty 0.5 ^
        --flare 0.02 --msd-nm 2.0 --blur-nm 10 --z6 0.02 --z11 0.02

  [무엇을 최적화하는지]

  목적은 'CD 오차 최소화' 가 아닙니다. dose_to_size 가 조건마다 따로 CD 를
  목표에 붙이므로, 어떤 설정을 고르든 공칭점 CD 오차는 0 입니다. 즉 그
  목적함수는 상수이고 어느 후보도 가릴 수 없습니다. 대신 **EL 10 % 에서의
  DOF 를 최대화**합니다. 설정을 가르는 것은 공칭점의 값이 아니라 거기서
  벗어날 때 CD 가 얼마나 빨리 어긋나는가이고, 그것이 공정 윈도입니다.

  [무엇을 넣어야 하는지]

  11 개 입력을 다 고르는 것이 아닙니다. 성격이 다릅니다.

    손잡이      na, sigma_out       스캐너에서 설정 -> 추천기가 찾습니다
    설계 요구   pitch, duty         --pitch / --duty 로 줍니다
    공구 상태   flare, msd_nm, blur_nm, z6, z11
                                    **측정해서** 넣는 값입니다
    교란        defocus             격자로 쓸어 윈도를 만듭니다
    윈도 축     dose_rel            윈도의 중심으로 나옵니다

  공구 상태를 0 으로 두면 '완벽한 장비' 가 되는데 학습 데이터에 그런 조건이
  없어서 거부됩니다. 거부되면 축마다 학습 범위를 인쇄하므로 그 안의 값으로
  다시 주십시오.

  [출력을 읽는 법 여덟 가지]

  (1) DOF 는 숫자 하나가 아니라 **구간**입니다. 'DOF 하한' 과 'DOF 상한'
      사이에 참값이 있습니다. 구간은 초점 격자와 노광 격자 **양쪽**의
      편향을 담습니다. 한쪽만 담으면 구간이 참값을 놓칩니다. 실제로 그렇게
      만들었다가 고쳤습니다. 해석해로 재어 보니 참 DOF 가 112.69 nm 인
      조건에서 옛 방식의 구간은 기본 격자에서 [0.0, 0.0] 이었습니다
      (VERIFICATION_LIMITS 65 번).

  (2) 순위는 **하한**으로 매깁니다. 상한으로 매기면 격자가 거친 후보가 위로
      올라옵니다. 모르면 모를수록 좋아 보이는 정렬은 쓸 수 없습니다.

  (3) '격자 미결정' 표가 따로 나오면 하한 0, 상한 양수인 후보입니다. 윈도가
      없다는 뜻이 **아니고**, 지금 격자로는 EL 10 % 에 닿는지 말할 수 없다는
      뜻입니다. 위 표의 0 과 뜻이 다릅니다. --n-dose 를 올려 EL 분해능을
      좁히면 하한이 올라오거나 상한이 0 으로 내려앉아 판정이 끝납니다.

        py recommend.py --models models/s_mlp --pitch 200 --duty 0.5 ^
            --flare 0.02 --msd-nm 2.0 --blur-nm 10 --z6 0.02 --z11 0.02 ^
            --n-dose 129

  (4) '포화' 표시는 윈도가 격자 경계에 닿았다는 뜻입니다. 그 DOF 는 하한일
      뿐이고, 격자가 좁아서 그렇게 나온 것인지 구분해야 합니다.

  (5) 추천기는 '모형 오차 출처' 를 인쇄합니다. 번들에 저장된 실측치(최악
      영역)를 쓰는 것이 기본이고, 없으면 11주차 상수를 씁니다. --rel-p95 로
      직접 줄 수도 있습니다. 다른 모형의 숫자를 쓰면 보수 공차가 조용히
      잘못 잡히므로 출처를 꼭 확인하십시오.

  (6) '보수 하한' 이 0 이면 모형 오차를 떼면 윈도가 남지 않는다는 뜻입니다.
      모형의 상대 95 백분위 오차가 공차를 거의 다 먹기 때문입니다. 두
      숫자와 그 차이는 추천기가 '보수 공차' 줄에 직접 인쇄하므로 여기에
      적어 두지 않습니다(적어 두면 모형을 다시 학습할 때마다 이 문서만
      낡습니다). 음수가 나오면 인증이 불가능하다는 뜻입니다.
      그래서 **이 표는 인증이 아니라 순위**입니다. 후보 비교에서는 오차가
      부분적으로 상쇄되므로 순위는 쓸 수 있습니다. 인증은 상위 후보를
      시뮬레이터로 되돌려 재는 13주차 몫입니다.

  (7) '추천 운전점' 표가 장비에 넣을 값입니다. 노광량은 **무차원 배율**
      이고(최적 초점에서 목표 CD 를 만드는 광강도를 1.0 으로 둔 값),
      업계의 E_op [mJ/cm^2] 와 이름만 같고 단위가 다릅니다. 물리 노광량이
      필요하면 데이터셋의 dose_clear_mj 를 쓰십시오.
      초점 오프셋은 최적 초점(dz=0) 기준 nm 입니다. 값은
      **공칭** 창의 **중심**이라 양쪽 여유가 같습니다. 공칭이므로 모형
      오차를 떼지 않은 값입니다. 부호 거울을 적용한 경우
      초점 오프셋은 이미 이 장비 기준으로 되돌려 적혀 있습니다.
      '제약 위반' 이 붙은 행의 운전점은 쓰지 마십시오. 창은 있지만 NILS
      또는 CDU 가 공차를 넘습니다.

  (8) '초점 격자를 dz=0 이 격자점이 되도록 재배치했다' 는 주의가 보이면
      정상입니다. 학습된 defocus 범위가 비대칭일 때 나옵니다. dz=0 을
      밟지 않으면 DOF 를 과대보고할 수 있어서 간격을 유지한 채 격자를
      옮깁니다. 끝을 최대 한 간격 버리므로 DOF 가 조금 작게 나올 수
      있는데, 작게 나오는 쪽은 안전한 방향입니다.

  [범주형 조건 : 편광, 조명, 마스크]

  데이터를 이산 조합(--arms)으로 생성했으면 이 세 가지가 모형 입력이
  됩니다. 값을 주지 않으면 추천기가 거부하면서 관측된 값을 보여 줍니다.
  기본값을 두지 않는 이유는, 이것이 결과를 크게 바꾸는 설계 선택이라
  조용히 하나를 고르면 고르지 않은 조건의 답을 받기 때문입니다.

    py recommend.py --models models/s --pitch 250 --duty 0.5 ^
        --flare 0.02 --msd-nm 2.0 --blur-nm 10.0 --z6 0.02 --z11 0.01 ^
        --pol TE --source conventional --mask binary

  조합 자체를 추천받으려면 --search-arms 를 주십시오. 표에 '이산 조합'
  열이 붙어 어느 조명·마스크가 창이 가장 넓은지 함께 나옵니다. 데이터에
  실재하는 조합만 돕니다.

    py recommend.py --models models/s --pitch 250 --duty 0.5 ^
        --flare 0.02 --msd-nm 2.0 --blur-nm 10.0 --z6 0.02 --z11 0.01 ^
        --search-arms

  관측되지 않은 값(예: --pol TM)은 거부합니다. 범주형은 보간이 없어서
  본 적 없는 수준의 예측은 뜻이 없습니다.


  [수차 부호]

  z6, z11 의 학습 범위는 양수뿐입니다. 그런데 CD(+초점,+수차) =
  CD(-초점,-수차) 가 정확히 성립하므로, 둘 다 음수인 장비는 부호를 뒤집어
  평가합니다(DOF 는 그대로, 최적 초점 오프셋의 부호만 뒤집힘). 부호가 섞인
  장비는 닿을 수 없는 등가류이므로 거부합니다. 다음 데이터 생성에서 두 축
  중 하나만 음수로 열면 표본을 더 뽑지 않고 해결됩니다.

  종료 코드 0 은 평가를 끝냈다는 뜻이며 추천이 공차를 만족한다는 뜻이
  아닙니다.


[6-2] 되돌림 검증 (13주차)

  추천기가 내놓은 조건을 **시뮬레이터로 다시 돌려** 대리 모형의 예측과
  대조합니다. 12주차는 "인증은 못 하지만 순위는 쓸 수 있다" 고 적었는데
  그 근거가 측정되지 않았습니다. 그것을 재는 것이 이 도구입니다.

    py roundtrip_w13.py --models models/s,models/s13,models/s13c \
        --pitch 250 --duty 0.5 --pol TE --source conventional \
        --mask binary --tool-preset regions

  --models 에 쉼표로 여러 번들 접두사를 줍니다. 모형이 여러 개면 전부
  보고합니다. 하나를 골라 적으면 사후선택입니다. 주 모형은 분포 내
  기준으로 **미리** 정해 두었습니다(보강명세_동결.md).

  --tool-preset regions 는 공구 상태(flare, msd, blur)를 번들 자신의
  축에서 읽어 구간별로 훑습니다. 생성 코드의 상수를 다시 적지 않습니다.

  읽는 법 (출력 맨 끝에도 같은 내용이 있습니다)

    - 순위는 **제약 통과군 안에서만** 봅니다. 추천기의 정렬 키가 제약을
      먼저 보므로 위반군은 DOF 가 훨씬 크고, 두 군을 섞으면 군 사이
      격차가 상관을 끌어올립니다. 실측으로 섞으면 +0.799, 통과군
      안에서는 -0.127 이었습니다. 부호가 뒤집힙니다.
    - 상위 k 겹침은 '제약 포함' 과 'DOF 만' 두 가지로 나옵니다. 추천이
      바뀐 이유가 **제약 판정 뒤집힘**인지 **DOF 순서 붕괴**인지 구분하기
      위한 것입니다. 둘은 고쳐야 할 곳이 다릅니다.
    - '서로 다른 DOF 값' 이 후보 수의 절반 미만이면 동률이 많다는 뜻이고,
      그때 상위 1 겹침은 정렬 안정성에 좌우되므로 믿지 마십시오.
    - '구간 포함' 은 대리 모형의 [하한, 상한] 이 실측을 담는지입니다. 그
      구간은 **격자 편향만** 담고 모형 오차의 신뢰구간이 아닙니다. 포함률
      이 낮은 것은 구간이 좁아서가 아니라 다른 것을 재는 구간이기
      때문입니다.
    - 실측 제약은 NILS 만으로 판정합니다. CDU 는 몬테카를로가 필요해
      재지 않았으므로, CDU 로만 떨어진 후보는 **비교 대상이 아니며**
      뒤집힘 집계에서 뺍니다.
    - '실측이 격자 미결정' 으로 나온 후보는 공정창이 없다는 뜻이 아니라
      하한 격자점에서 EL 목표를 못 넘겼다는 뜻입니다. --n-focus /
      --n-dose 를 늘려 다시 재야 하며, 그 후보의 DOF 차를 '모형이
      낙관적' 으로 읽으면 안 됩니다.

  몬테카를로 교차검사는 **공차 대비**로 판정합니다(--mc-tol, 기본 0.05).
  표준오차 배수는 참고로만 찍습니다. 그 표준오차는 행 사이 독립을
  가정하는데 2 차원 블러가 그 독립을 깨므로 낙관적이고, 실측에서 CD 의
  0.01 % 차이에 9.17 배 실패가 났습니다.

  이 도구 자신의 회귀는 py validate_w13.py 입니다 (16 사례 204종).


[6-3] DOF 예측의 적합예측 구간 보정 (13주차)

  "이 DOF 를 얼마나 믿는가" 에 **피복 보장이 있는** 답을 붙입니다. 추천기가
  내놓는 'DOF 하한/상한' 은 격자 편향만 담고 모형 오차를 담지 않습니다.

    py calibrate_w13.py --models models/s13c \
        --dataset dataset/merged13c.npz \
        --n-cal 60 --n-test 40 --alpha 0.10 \
        --n-focus 33 --n-dose 21 --focus-span 600 --dose-span 0.30

  무엇을 하는가 : 데이터셋 **검증 분할**의 광학 조건에서 대리 모형 DOF 와
  시뮬레이터 DOF 를 짝지어 잔차를 모으고, 유한 표본 보정을 쓴 분위수 q 를
  냅니다. 그리고 **시험 분할**에서 같은 q 의 실측 피복률을 셉니다. 보정에
  쓴 분할에서 재면 당연히 맞으므로 그것은 검증이 아닙니다.

  왜 데이터셋의 9x9 격자를 쓰지 않는가 : 그 격자는 적격 영역에 5 % 여유만
  두고 잡혀 참 공정창이 거의 항상 경계에 닿습니다. 보성 곡선과 대칭 공차
  에서는 초점 경계와 노광 경계가 동시에 안쪽일 수 없다는 것이 산수로
  나옵니다. 그래서 **추천기가 쓰는 격자**에서 보정합니다.

  결과 쓰기

    py recommend.py ... --conformal models/s13c_conformal.json
    py roundtrip_w13.py ... --conformal models/s13c_conformal.json

  보정 파일은 **모형 하나**에 대한 것입니다. 3 모형을 함께 돌릴 때 한
  파일을 주면 그 모형에만 구간을 적고 나머지에는 적지 않습니다. 모형마다
  따로 보정해야 셋 다에 구간이 붙습니다.

  격자 설정(--n-focus, --n-dose, --focus-span, --dose-span, --el, 피치,
  duty)이 보정 때와 **하나라도 다르면** 양쪽이 구간을 적지 않고 경고합니다.
  DOF 는 격자에서 읽는 값이라 격자가 다르면 다른 양이고, 그때 구간을 적는
  것은 보장 없는 숫자에 보장 딱지를 붙이는 일입니다.

  읽을 때 주의할 것

    - 보장은 **시뮬레이터 대비**이고 웨이퍼 대비가 아닙니다.
    - 보정 조건은 데이터셋 검증 분할이고 적용은 최적점 근처이므로 분포가
      이동합니다. 되돌림이 실측 피복률을 따로 재니 두 숫자를 나란히 보십시오.
    - q 가 초점 격자 간격의 2.5 배 이하이면 구간이 모형 오차보다 격자
      분해능을 재고 있을 수 있습니다. --n-focus 를 늘려 q 가 **안정되는지**
      보십시오. 줄어드는지가 아닙니다 — 실측으로 초점 17 점 75.0 nm ->
      33 점 93.8 nm -> 61 점 90.0 nm 로 커지며 수렴했습니다.
    - 보정 표본이 모자라면 구간을 만들지 않고 필요한 수를 적습니다
      (alpha 0.10 이면 최소 9 개). 최댓값으로 때우지 않습니다.


[6-4] 주장 3의 계측 규격 (13주차)

  "MSD 와 블러는 잡음으로 분리된다" 를 **얼마나 정밀하게 재야 분리되는가**
  로 바꿉니다. 음성 결과가 요구 규격이 됩니다.

    py metrospec_w13.py
    py metrospec_w13.py --scan
    py metrospec_w13.py --msd 4.5 --blur 7.0 --target 1.0
    py metrospec_w13.py --sigma-cd 0.5 --ler-rel 0.10 --n-seeds 6

  데이터셋도 모형도 필요 없습니다. 시뮬레이터만 씁니다. 조건은 주장 3
  (verify.py H5)과 같게 고정되어 있어 기존 주장을 잇습니다.

  읽는 법

    - 먼저 [축퇴 확인] 을 봅니다. 결정론 CD 범위가 0 이어야 이 분석의
      전제가 섭니다. 0 이 아니면 도구가 숫자를 내지 않고 종료 코드 1 을
      돌려줍니다.
    - '측정 평균 범위' 가 0 이 아닌 것은 정상입니다. 결정론 평균은 축퇴
      이지만 **측정되는 평균은 축퇴가 아닙니다**(역치 추정기가 비선형).
      축퇴를 깨는 경로가 LER 하나가 아니라 둘이라는 뜻입니다.
    - `교차곱 D` 가 0 이면 어떤 정밀도로도 분리되지 않습니다. **사이각만
      보면 안 됩니다** — 180 도는 0 도만큼 나쁩니다(반평행도 공선).
      실측 사이각이 149~165 도라 '잘 갈린다' 로 오독하기 쉽습니다.
    - '한계가 되는 관측량' 이 블러는 LER, MSD 는 CD 입니다. MSD 를 재려면
      고쳐야 할 장비가 LER 이 아니라 CD 라는 뜻입니다.
    - 필요한 LER 정밀도는 **상대값**(% )으로만 옮겨 쓸 수 있습니다. 이
      과제의 LER 은 산탄 잡음만 고려한 하한이라 절대 크기가 실제보다
      작습니다.
    - --scan 은 '어디서 재야 하는가' 를 답합니다. MSD 높고 블러 낮은 쪽이
      유리해 CD 지점 수가 210 대 572 로 2.7 배 차이 납니다.

  이 도구 자신의 회귀는 validate_w13.py Case 13 입니다 (39 종).

[8] 식별 가능성 분석

  사이트의 "식별 가능성" 탭에서 실행합니다. 미지수로 둘 변수를 고르고
  버튼을 누르면 Cramér-Rao 하한과 민감도 사이각이 나옵니다.

  핵심은 이렇습니다. 미지수를 적게 둘수록 한계가 내려갑니다. 즉 따로
  측정해서 아는 변수가 많을수록 나머지를 정확히 되짚을 수 있습니다.

  5 변수를 모두 미지수로 두면 초점 하한이 '무한' 으로 나옵니다. 숫자가
  크다는 뜻이 아니라, Fisher 정보 행렬에 영공간이 생겨 그 방향으로는
  관측이 전혀 변하지 않는다는 뜻입니다(구조적 비식별). 플레어를 미지수에서
  빼면 영공간이 사라져 0.0257 nm 가 됩니다.

  반면 노광량을 10 에서 1000 mJ/cm^2 로 100 배 올려도 무한에서 무한입니다.
  즉 계측을 하나 더 하는 것이 광자를 100 배 쓰는 것보다 비교가 안 될 만큼
  효과적입니다. 이것이 이 과제의 핵심 결론입니다.

  [하한 인용 시 주의] 하한은 총 광자 예산의 제곱근에 반비례합니다. 위
  0.0257 nm 는 '선 길이 2 um 를 30 mJ/cm^2 에서 평균했을 때' 의 값이며,
  계측 조건을 함께 적지 않으면 의미가 없습니다.
